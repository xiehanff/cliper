# Cliper Flutter 重构实施清单

这份清单配合 [flutter-rebuild-spec.md](D:/xiehan/flutter/cliper/docs/flutter-rebuild-spec.md) 使用。

目标不是讨论方案，而是把工作拆成可并行、可验收、可勾选的任务。多个 agent 执行时，先看依赖，再认领任务，不要越界修改。

## 使用规则

- 开工前先通读规格文档。
- 每个任务完成后，再勾选，不要预先打勾。
- 如果任务阻塞，直接在对应任务下补充阻塞说明。
- 不要跨任务顺手重构未分配模块。
- 如果多个 agent 并行，只允许一个 agent 负责“总装配”和“最终联调”。
- 当前阶段只考虑 Windows 交付，macOS 相关验证与调整不纳入本轮任务。

## 并行分工建议

推荐分成 5 条工作流：

1. 基础架构与装配
2. 数据与业务规则
3. UI 复刻
4. 桌面系统能力
5. 测试与验收

建议顺序：

- 先完成 A、B
- 然后 C、D 并行
- 最后 E 和 F

## Agent 认领模板

多个 agent 并行时，建议按下面格式认领，避免冲突：

```text
Agent:
负责模块:
任务编号:
计划修改路径:
依赖前置是否完成:
预计风险:
```

示例：

```text
Agent: agent-ui-1
负责模块: UI 复刻
任务编号: C3, C4, C5, C6
计划修改路径: lib/presentation, lib/core/theme, lib/core/l10n
依赖前置是否完成: A3/B6 已完成
预计风险: 颜色选择器与外部点击判定可能和窗口隐藏逻辑冲突
```

## 冲突规避规则

- `pubspec.yaml`、`bootstrap.dart`、`AppController`、平台原生目录，默认视为高冲突文件。
- 高冲突文件同一时间只允许一个 agent 修改。
- UI agent 不改平台原生代码。
- 平台 agent 不顺手重写 UI 结构。
- 测试 agent 不在没有沟通的情况下改业务规则。

## 建议认领组合

如果只有 2 个 agent：

- Agent 1：A + B + E
- Agent 2：C + D + F

如果有 3 个 agent：

- Agent 1：A + B
- Agent 2：C
- Agent 3：D + F

如果有 4 个 agent：

- Agent 1：A + E
- Agent 2：B
- Agent 3：C
- Agent 4：D + F
